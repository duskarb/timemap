# 대전 시간지도 — 웹 비주얼라이제이션

거리가 아니라 **이동 시간**으로 그린 대전. 출발 정거장을 고르면 현재와 트램 도입 후의
도달 범위가 어떻게 달라지는지 보여줍니다.

## 실행

`index.html` 을 브라우저로 열면 됩니다. 빌드도 서버도 필요 없습니다.
데이터를 `fetch` 대신 `data/daejeon.js` 의 전역 할당으로 싣기 때문에 `file://` 에서도 그대로 동작합니다.

## 구조

```
대전_시간지도/
├─ index.html          마크업
├─ assets/fonts/       큰부리새 Bold 제목 + KIMM Bold 강조 서체
├─ assets/figma/       Figma 원본 출발지 핀 자산
├─ css/style.css       포스터 A1의 색·타이포 토큰
├─ js/app.js           그래프·모델·SVG 지도/캔버스 히트맵 렌더러
└─ data/daejeon.js     지오메트리 · 정거장 · 그래프 · 도달권 그리드
```

`js/app.js` 는 위에서 아래로 이렇게 읽힙니다.

| 구간 | 하는 일 |
| --- | --- |
| 정거장 · 그래프 | 1호선 22역 + 트램 45정거장 인접 리스트 |
| `arriveTimes` | 다중 시드 다익스트라 — 출발점에서 모든 정거장까지 |
| `makeModel` | 임의 지점 소요시간 = min(도보, 버스, 궤도 + 하차 도보/연계버스) |
| `layout` / `fitGeo` | 제목 뒤에서 우측 지표 직전까지 흐르는 70% 포스터 무대에 지도를 배치 |
| `calibrate` | 분→px 축척을 **현재 시나리오 하나로 고정** — 두 시간지도가 공유 |
| `radial` | 반지름 = 소요시간 × 고정 축척 (선형) |
| `tmAreaPx` | 화면에 그려진 시간지도의 픽셀 면적 — 축척 보정과 축소율 표시에 함께 씀 |
| `ROUTES` / `curveD` | 노선과 구 경계가 같은 중심형 Catmull-Rom 곡선을 쓴다 |
| `chainCuts` | 구 쌍마다 따로 뽑히는 공유 경계를 곧게 이어지는 짝끼리 한 줄로 잇는다 |
| `boundaryPathD` | 구 경계를 그리며 화면 간격으로 꼭짓점을 솎고 눌린 조각을 뺀다 |
| `smoothRadius` | 경계선은 반지름만 평활화(방위는 실제값 유지) |
| `tweenTo` / `step` | 지리 ↔ 시간 모프 (cubic-in-out, 1.4초) |

## 네 가지 뷰

- **지리 지도** — 실제 거리
- **시간 · 현재** — 1호선 + 버스 기준 시간지도
- **시간 · 트램 후** — 현재 시간지도를 연두로, 트램 도입 후를 주황으로 겹쳐 비교
- **단축 시간** — 트램으로 시간이 줄어드는 지역을 격자로 표시

정거장 정보(현재 / 트램 후 / 단축)는 **마우스를 정거장 위에 올렸을 때만** 뜹니다.
클릭은 출발지 변경, 터치는 툴팁 없이 출발지 변경만 합니다.
스크롤 입력은 240ms 동안 모은 뒤 한 번의 부드러운 확대·축소 애니메이션으로 전환합니다.
노선과 점선은 화면 픽셀 굵기를 유지하고, 정거장·출발지 마커와 구 경계선만 제한된 범위 안에서
확대율에 반응합니다. 구 경계선 굵기는 지리 지도 폭에서 뽑기 때문에 창 크기에 따라서도 달라집니다
(1440×900에서 2.6px, 375px 화면에서 하한인 1.6px).

5개 구를 나누는 경계는 쌍으로 따져 정확히 7개이고, **어느 뷰에서도 하나도 빠지지 않습니다.**
시간지도는 구역마다 압축률이 달라서 가장 짧은 중구↔대덕구(1.15km)가 20px까지 눌리는데,
길이를 기준으로 조각을 걸러 내면 그 두 구가 화면에서 한 덩어리로 붙어 버립니다.

## 시간 모델

**공표 수치** — 트램 표정속도 22.06km/h · 본선 33.9km · 정거장 45개 · 첨두 배차 7분 30초 ·
1호선 20.5km / 표정속도 33.5km/h · 개통 2030년 하반기(2026.6 대전시 발표).

**가정** — 직선거리 우회계수 1.3 · 도보 4.55km/h ·
시내버스 접근·대기 10분 + 표정속도 16km/h + 5km 초과 시 환승 7분 · 환승 도보 2분 + 거리 ·
철도 하차 후에는 도보 또는 연계버스(환승도보 2분 + 대기 3분 + 16km/h) 중 빠른 쪽.

버스 계수는 공표 자료가 없어 비교용으로 둔 값입니다. `단축 시간` 뷰는 두 시나리오의
**차이**만 보므로 이 가정의 영향을 가장 적게 받습니다.

하차 후 연계버스를 넣지 않으면 역세권 **밖**에서는 철도가 영원히 도보 열세라
시간지도가 노선에 거의 반응하지 않습니다(시 경계 기준 트램 전후 면적비 1.000).
연계버스를 넣은 뒤에야 트램 수혜지의 축소가 드러납니다.

## 축척 — 왜 지도가 줄어 보이는가

두 단계의 성격이 다르고, **두 번째가 더 세게** 읽히도록 잡았습니다.

- **지리 → 현재**(약): km에서 분으로 단위가 바뀌는 축척 변경일 뿐이므로, 현재 시간지도
  면적을 지리 지도의 88%(`NOW_VS_GEO`)로 맞춰 약한 축소로 둡니다.
- **현재 → 트램 후**(강): 분→px 환산을 **현재 시나리오 하나로 고정**해 두 지도가 함께 씁니다.
  크기 차이는 전부 실제 소요시간 차이이고, 반지름이 시간에 정비례(`POW = 1`)하므로
  화면 면적비 = 카드에 찍히는 숫자입니다.

시간지도 블롭은 출발지에서 멀리 뻗어 길쭉합니다. 반지름 예산 안에 다 넣으면 면적이 지리
지도의 55~70%까지 떨어져 첫 단계가 두 번째보다 커집니다. 기본 지도가 화면에서 충분히 크게
읽히도록 포스터 무대의 98%(`GEO_FILL`)를 사용하고, 단계 간 면적비는 별도로 유지합니다.
2048×1266 첫 화면에서 지도 바운딩 영역은 화면의 약 70.7%입니다. 실측(1440×900):

| 출발지 | 지리 → 현재 | 현재 → 트램 후 |
| --- | --- | --- |
| 관저네거리(기본) | −12.7% | **−33.2%** |
| 진잠네거리 | −18.1% | **−32.8%** |
| 대전복합터미널 | −12.0% | **−30.4%** |
| 정부청사 | −12.0% | −5.0% |
| 대전역 | −12.0% | −3.2% |

1호선 역에서 출발하면 트램 전후 차이가 3~5%라 두 번째 단계가 약해집니다. 이건 축척이
아니라 데이터가 그렇습니다. 기본 출발지를 관저네거리로 둔 이유이고, 우측 카드도 그 경우
"이미 1호선이 지나는 곳이라 변화가 작습니다"라고 밝힙니다.
